# 🐺 狼人殺 — 智慧 AI 補位多人連線版

一個在瀏覽器中執行的狼人殺（Werewolf / Mafia）社群推理遊戲。玩家可以單人挑戰全 AI 對手，也可以開房與朋友連線遊玩；房間人數不足時，缺額座位會自動由 AI 補位，玩家中途斷線也會無縫交由 AI 接手，遊戲不會因此中斷。AI 玩家的發言由 Google Gemini 模型生成。

## 專案簡介

這是一個全端小型專案：後端以 FastAPI 提供單一 WebSocket 端點驅動遊戲邏輯與房間大廳，並直接把 `frontend/` 目錄當靜態網站送出；前端則是不依賴框架的原生 HTML / CSS / JavaScript。遊戲支援兩種進入方式：

- **單人模式**：你加入一場遊戲，其餘座位全由 AI 玩家填滿。
- **多人大廳**：建立或加入 4 碼房號的房間，與其他真人玩家同場，缺額座位一樣由 AI 補位。
- **上帝模式**：不親自下場，純粹旁觀一整場全 AI 對戰，並可暫停 / 繼續遊戲進度。

## 特色功能

- 6～12 人局，內建對應人數的狼人 / 村民 / 預言家 / 女巫身份分配表（見〈遊戲玩法〉）。
- 玩家斷線時，遊戲不中斷：AI 立即接管該玩家的行動與發言。
- 每位 AI 玩家會隨機分配一種說話風格（如謹慎分析型、直覺型、質問型等），讓發言更像真人。
- 上帝模式下可即時暫停 / 繼續遊戲，並看到所有陣營的私密聊天（例如狼人夜間密語）。
- 遊戲結束會揭曉全部玩家的真實身份與對戰紀錄。

## 快速開始

> [!IMPORTANT]
> 需要一組可用的 Google Gemini API 金鑰（`google-genai` SDK），且金鑰目前是直接寫在原始碼 `backend/config.py` 中，請見〈設定〉一節的風險說明。

1. 安裝後端依賴（`backend/requirements.txt`：`fastapi`、`uvicorn`、`websockets`、`google-genai`、`pydantic`）：

   ```bash
   pip install -r backend/requirements.txt
   ```

2. 於 `backend/config.py` 填入你的 Gemini API 金鑰（見下方〈設定〉）。

3. 啟動伺服器：

   ```bash
   python backend/main.py
   ```

   伺服器會在 `http://0.0.0.0:8765` 啟動，同時提供遊戲頁面（靜態檔）與 WebSocket 端點（`/ws`）。

4. 用瀏覽器開啟 `http://localhost:8765`，選擇「單人模式」或「多人大廳」開始遊戲。
5. 可用 `GET /health`（回傳 `{"status": "ok"}`）確認伺服器是否正常運作。

## 設定

所有設定集中在 `backend/config.py`：

| 設定項 | 說明 |
| --- | --- |
| `API_KEY` | Gemini API 金鑰，直接以字串寫入此檔，程式沒有讀取任何環境變數或 `.env` 檔。 |
| `PRIMARY_MODEL` / `FALLBACK_MODEL` | 主要與備援的生成模型名稱；主模型逾時或連續失敗（含 429 / 500）時會自動切換到備援模型重試。 |
| `LLM_TIMEOUT` | 單次模型呼叫的逾時秒數（預設 60）。 |
| `LLM_MAX_RETRIES` | 每個模型的最大重試次數（預設 5）。 |
| `MIN_PLAYERS` / `MAX_PLAYERS` | 允許的房間人數範圍（預設 6～12），伺服器端會依此拒絕不合法的人數設定。 |
| `ROLE_NAMES` / `ROLE_DISTS` | 各角色的顯示名稱，以及各人數局對應的身份分配表。 |

> [!WARNING]
> 儲存庫的 `.gitignore` 忽略了 `.env`，但目前程式碼並未讀取任何 `.env` 檔案或環境變數——金鑰只會生效於直接寫入 `backend/config.py` 的值。若要提交程式碼或公開儲存庫，請自行避免把真實金鑰留在 `config.py` 中，或自行改造成從環境變數讀取。

## 遊戲玩法

一場遊戲依序進行「夜晚」→「白天發言」→「投票」，直到達成勝利條件（狼人陣營人數 ≥ 好人陣營人數則狼人獲勝；場上狼人全滅則好人獲勝）。

- **狼人**：夜晚共同選擇一名目標淘汰，狼人之間有專屬的密語頻道。
- **預言家**：每晚查驗一名玩家的陣營（狼 / 非狼）。
- **女巫**：持有一瓶解藥與一瓶毒藥，可在夜晚選擇救人或下毒，兩者皆為一次性道具。
- **村民**：沒有夜間技能，僅能靠白天發言與投票影響局勢。

各人數局的身份分配（人數含所有玩家，真人與 AI 混合）：

| 玩家人數 | 狼人 | 村民 | 預言家 | 女巫 |
| --- | --- | --- | --- | --- |
| 6 | 2 | 2 | 1 | 1 |
| 7 | 2 | 3 | 1 | 1 |
| 8 | 2 | 4 | 1 | 1 |
| 9 | 3 | 4 | 1 | 1 |
| 10 | 3 | 5 | 1 | 1 |
| 11 | 3 | 6 | 1 | 1 |
| 12 | 3 | 7 | 1 | 1 |

## 專案結構

```
backend/
  main.py           FastAPI 應用、WebSocket 端點、靜態檔案伺服器（進入點）
  game.py           房間大廳（LobbyManager / Room）與遊戲引擎（GameEngine）
  llm.py            組出各角色的 AI 提示詞，並呼叫 Gemini API
  config.py          API 金鑰、模型名稱、人數限制、角色設定
  requirements.txt   後端 Python 依賴
frontend/
  index.html         單頁式前端（設定頁 / 房間等待頁 / 遊戲頁 / 結算 Modal）
  js/websocket.js     WebSocket 連線與訊息收發封裝
  js/game.js          遊戲畫面渲染與各類事件處理
  js/app.js           頁面切換、大廳與房間操作的互動邏輯
  css/style.css       樣式
```

## 技術棧

- **後端**：Python、FastAPI、原生 WebSocket（`fastapi.WebSocket`）、`uvicorn`、`google-genai`（Gemini API 客戶端）。
- **前端**：原生 HTML / CSS / JavaScript，無建置流程、無前端框架依賴。
- 前端與後端由同一個 FastAPI 行程提供（`backend/main.py` 同時服務 `frontend/` 靜態檔），開發與部署皆只需啟動這一支程式。

## 已知限制

- **狀態僅存於記憶體**：房間與遊戲進度都存在行程記憶體中，伺服器重啟或程序終止即全部遺失，沒有資料庫或持久化機制。
- **無存取控制**：房間僅以 4 碼房號區分，沒有帳號、密碼或其他驗證機制，知道房號即可加入。
- **金鑰以明碼寫在原始碼中**：見〈設定〉一節的說明與風險提醒。
- 儲存庫內未發現自動化測試、CI 設定、Dockerfile 或其他部署設定檔。
