# Library-First

[English](library-first.md) | **繁體中文**

> 本文件位於 `docs/`。skill 本體位於 [`library-first/SKILL.md`](../library-first/SKILL.md)。

一個在「動手寫共通機制」之前先擋一次的 skill：花一次搜尋評估現成方案，再決定要不要自己寫。

每一行自製程式碼都是負債——要維護、要測試、要寫文件，還要處理沒人想過的邊界情況。這個 skill 不是要求一律用套件，而是要求這個決定**被明講出來**，而不是預設自己寫。

## 觸發時機

準備手刻下列這類通用機制時：

重試與退避（retry / backoff）、驗證、日期時間處理、狀態管理、認證授權、快取、序列化、CLI 參數解析、密碼雜湊。

**不適用**於領域專屬的商業邏輯——訂單折扣規則、保費計算、遊戲規則本來就沒有、也不該有現成套件。

## 流程

1. **命名問題**——用領域詞彙描述，不要用自己的變數名。是「exponential backoff retry」，不是「`callApiAgain` 裡那段邏輯」。
2. **搜對生態系**——不要預設 npm。Python 有 PyPI、C# 有 NuGet、Go 有 pkg.go.dev、Rust 有 crates.io。同時檢查標準函式庫，很多需求根本不必新增依賴。
3. **套用品質門檻**——沒通過門檻的套件不算「現成方案」，這時自己寫才是對的。
4. **做出決定並說明理由**——明確講「用了 X，因為 Y」或「自己寫，因為 Z」。不要默默決定。

## 品質門檻

要取代自製程式碼，套件必須**全部**滿足：

- **確實存在**：這個名稱能在該語言的 registry 解析出來，決策裡引用的版本號也來自這次查詢。憑印象想起來的名稱只是搜尋詞，不是套件——看起來合理卻查不到的名稱，正是供應鏈攻擊者搶註的目標
- **仍在維護**：近 12 個月內有 commit，未標記 deprecated 或 unmaintained
- **依賴樹合理**：為了一個小功能拉進數十個傳遞依賴通常划不來
- **授權相容**：確認與專案授權無衝突（閉源專案碰到 GPL 是硬停）
- **體積與用途相稱**：前端 bundle size 有意義時，200KB 的套件取代 20 行不划算
- **API 不侵入**：導入不應該要求重構周邊架構

不確定是否符合時，**去查，不要猜**。

## 四種「自己寫才對」的情況

- **領域專屬商業邏輯**
- **效能關鍵路徑**——有實際量測支撐，通用函式庫的抽象成本在熱路徑上不可接受
- **安全敏感、需完全掌控**——每一行都要能稽核，不透明的依賴不可接受
- **已評估現成方案且確實不足**——重點是**已評估**，不是假設不足

## 安裝

請在倉庫根目錄讓 `skills` CLI 自動偵測相容 agent，並安裝此 skill：

```bash
npx skills add . --skill library-first
```

若要安裝到個人層級，請加上 `--global`；未加時為專案層級。若採手動安裝，請把 `library-first/` 複製到 host 文件指定的 skills 目錄，不要假設特定 runtime 路徑。

> [!NOTE]
> 第一次執行 `npx` 可能會下載 CLI。若 host 只在 session 啟動時偵測 skill，安裝後請重新載入或重啟。
